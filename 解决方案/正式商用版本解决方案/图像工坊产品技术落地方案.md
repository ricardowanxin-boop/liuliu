# 图像工坊产品技术落地方案

版本：v1.0  
日期：2026-04-24  
适用对象：刘刘电商图片生产、商品图精修、批量素材生成、社媒内容出图工作流

## 1. 项目定位

“图像工坊”是一个面向电商运营和内容团队的 AI 图片生产工作台。它不是单纯的聊天式生图工具，而是把“提示词、参考图、批量队列、结果管理、素材库、API 调用成本”集中到一个可控的生产界面里，服务于商品主图、详情图、社媒配图、广告图、App/UI 概念图等场景。

根据设计图，产品核心体验为：

- 左侧：项目入口、模式切换、预设风格、历史记录、素材库。
- 中间：提示词编辑、提示词灵感、参考图上传、模型与尺寸参数、生成按钮。
- 右侧：结果画廊、图片下载、结果筛选与缩放。
- 底部：批量队列，展示每张图的生成状态、进度、尺寸和文件名。

产品目标是让运营人员不需要理解复杂 API，也可以稳定完成“上传参考图 -> 写需求 -> 生成多版 -> 下载/入库 -> 批量复用”的工作流。

## 2. 能力边界

本产品可以落地的能力：

- 文生图：根据提示词生成商品图、场景图、广告图、UI 设计稿。
- 图生图/参考图生成：上传商品图、手稿、截图或风格图，生成新的图片版本。
- 局部编辑：通过提示词或后续遮罩能力，对背景、材质、颜色、风格、构图做调整。
- 批量生成：同一套参数下批量生成多张图片，支持队列、进度、失败重试。
- 预设模板：沉淀产品摄影、生活方式、社交媒体、App 界面、营销广告等模板。
- 结果管理：生成结果进入画廊，支持下载、收藏、历史回看、项目归档。
- 成本与额度：展示 API 密钥连接状态、额度消耗、任务用量和用户级限制。

不建议承诺的能力：

- 不承诺 100% 精确复刻原图局部细节，AI 编辑需要人工验收。
- 不做第三方水印的直接移除工具，应改为“基于参考图重新生成原创图片”。
- 不把 OpenAI 模型或 Codex 内置 `image_gen` 能力复制到本地，只能通过 API 或服务端代理接入。
- 不把 API Key 暴露给浏览器端，所有模型调用必须走服务端。

## 3. 用户角色

运营人员：

- 负责上传商品图、选择预设、填写提示词、下载结果。
- 关注是否好看、是否能用于商品页、小红书、朋友圈或广告素材。

设计/视觉人员：

- 负责维护风格预设、提示词模板、出图规范、品牌视觉规则。
- 关注色彩、构图、材质、字体、统一性。

管理员：

- 负责配置 OpenAI API Key、额度、用户权限、并发限制、素材库目录。
- 关注成本、安全、日志、失败率和接口稳定性。

## 4. 核心业务流程

### 4.1 单张生成流程

1. 用户选择“生成”模式。
2. 选择预设，例如“产品摄影”。
3. 输入提示词，例如“一张干净的产品照片：薰衣草紫水晶珠与珍珠点缀的手链，放在透明亚克力托盘上。”
4. 选择模型、尺寸、质量、输出格式。
5. 点击“生成”。
6. 后端创建任务并调用 OpenAI 图片接口。
7. 图片生成完成后写入对象存储和数据库。
8. 前端右侧结果区刷新，用户可下载或加入素材库。

### 4.2 参考图编辑流程

1. 用户选择“编辑”模式。
2. 上传 1 张或多张参考图。
3. 输入编辑需求，例如“更换为 ins 风浅色背景，保留紫色手链，统一透明带钻指甲。”
4. 后端上传参考图并调用图片编辑接口。
5. 结果生成后进入结果画廊。
6. 用户可继续基于结果追改，形成多轮编辑记录。

### 4.3 批量生成流程

1. 用户选择“批量”模式。
2. 输入多行提示词，或从 Excel/CSV 导入商品信息。
3. 系统拆分为多个任务，进入底部批量队列。
4. Worker 按并发限制逐个调用模型。
5. 每个任务展示“排队中、生成中、已完成、失败”。
6. 完成后支持批量下载、批量入库、批量导出记录。

## 5. 功能模块设计

### 5.1 项目与素材管理

功能：

- 新建项目。
- 项目内保存提示词、参考图、生成结果、批量任务。
- 素材库支持按项目、品类、风格、用途筛选。

建议字段：

- 项目名称。
- 项目类型：商品图、社媒图、广告图、UI 设计稿。
- 所属客户/店铺/商品。
- 创建人、创建时间、最后更新时间。

### 5.2 提示词工作台

功能：

- 大文本提示词编辑器。
- 字数统计，例如 `56 / 1200`。
- 提示词灵感标签，例如“产品图、柔和日光、极简背景、俯拍、特写”。
- 预设模板自动拼接。
- 常用负面约束，例如“不要水印、不要文字、不要多余手指、不要畸变”。

建议做法：

- 前端展示用户输入的自然语言。
- 后端在调用模型前生成“增强提示词”，把场景、主体、风格、构图、光线、约束合并。
- 同时保存原始提示词和增强提示词，方便回溯。

### 5.3 参考图上传

功能：

- 支持 JPG、PNG、WebP。
- 单张建议限制 20MB 内，生产环境可提升到 50MB。
- 支持多图参考，例如商品主体图、风格图、背景图。
- 上传后生成缩略图，方便用户确认。

技术实现：

- 前端使用拖拽上传组件。
- 后端接收文件后上传到对象存储。
- 数据库保存原图 URL、缩略图 URL、文件大小、MIME 类型、hash。
- 调用 OpenAI 图片编辑接口时使用文件二进制、URL 或文件 ID，具体取决于最终选用 SDK 与接口形式。

### 5.4 参数控制

设计图中已有参数：

- 模型：默认显示 `gpt-image-2`。
- 尺寸：例如 `1024 x 1365 (4:5)`。
- 质量：高。
- 输出格式：PNG。
- 高级选项。

落地建议：

- 模型配置做成后台可配置项，不写死在前端。
- 如果目标 OpenAI 账户暂未开放设计图中的模型名，则切换到当前账户可用的 GPT Image 模型。
- 尺寸预设按电商场景提供：1:1 主图、4:5 内容图、3:4 海报图、16:9 横幅图、9:16 竖屏图。
- 输出格式支持 PNG、JPG、WebP。
- 高级选项包含背景透明、压缩质量、生成张数、随机种子/风格强度（若 API 支持）、负面提示词。

### 5.5 结果画廊

功能：

- 网格展示生成结果。
- 下载单张图片。
- 多选图片。
- 收藏/入库。
- 查看生成参数。
- 复制提示词。
- 继续编辑。

建议增加：

- 对比视图：参考图 vs 生成图。
- 版本链路：原图 -> 第一次编辑 -> 第二次编辑。
- 图片评分：用户给结果打分，沉淀优质提示词。

### 5.6 批量队列

状态：

- 排队中。
- 生成中。
- 已完成。
- 失败。
- 已取消。

功能：

- 实时进度。
- 单任务取消。
- 全部取消。
- 失败重试。
- 清除已完成。
- 批量下载。

技术实现：

- 后端用任务队列管理批量生成。
- 任务状态写数据库。
- 前端通过 WebSocket 或轮询获取进度。
- Worker 控制并发，避免触发 API 速率限制。

## 6. 技术架构

### 6.1 推荐架构

```text
浏览器前端
  ↓
Web 后端 API
  ↓
任务队列 / Redis
  ↓
AI Worker
  ↓
OpenAI Images API
  ↓
对象存储 / CDN
  ↓
数据库记录
```

### 6.2 前端技术

推荐：

- Vue 3 + Vite + TypeScript，适合中文团队快速交付。
- 或 React + Next.js + TypeScript，适合后续 SaaS 化和服务端能力整合。
- UI 组件库可选 Naive UI、Ant Design Vue、Element Plus，设计图这种工作台风格更适合轻量定制。

核心页面：

- `/projects` 项目列表。
- `/workspace/:projectId` 图像工作台。
- `/assets` 素材库。
- `/history` 历史记录。
- `/settings/api` API 与额度设置。

关键前端组件：

- `ModeSidebar` 模式侧栏。
- `PromptEditor` 提示词编辑器。
- `PresetPanel` 预设面板。
- `ReferenceUploader` 参考图上传。
- `GenerationControls` 参数控制区。
- `ResultGallery` 结果画廊。
- `BatchQueue` 批量队列。
- `TaskProgressCard` 任务进度卡片。

### 6.3 后端技术

推荐：

- Node.js + NestJS，适合做 API 网关、任务队列、权限和 WebSocket。
- PostgreSQL 存业务数据。
- Redis 存任务队列、进度状态、限流计数。
- 对象存储使用 S3、Cloudflare R2、阿里云 OSS 或腾讯云 COS。
- CDN 加速图片访问。

后端职责：

- 保存 API Key，不让前端接触密钥。
- 统一封装 OpenAI 图片接口。
- 处理上传、压缩、缩略图、格式校验。
- 创建任务、调度队列、失败重试。
- 记录成本、用量、日志。
- 管理项目、素材、历史记录、用户权限。

### 6.4 AI Worker

Worker 单独负责耗时任务：

- 从队列读取生成任务。
- 组装最终提示词。
- 调用 OpenAI 图片生成或编辑接口。
- 解析 base64 图片结果。
- 上传图片到对象存储。
- 更新任务状态和结果 URL。

这样做的好处：

- Web API 不会因为生成图片而长时间阻塞。
- 批量任务可以独立扩容。
- API 失败可以重试，不影响用户界面。
- 后续可以接入多个模型供应商。

## 7. OpenAI 图片能力接入

根据 OpenAI 官方文档，图片能力可通过 Images API 处理生成和编辑：生成接口用于根据文本创建图片，编辑接口用于结合输入图片与提示词生成新的结果。GPT Image 类模型支持尺寸、质量、输出格式、背景等参数，图片结果通常以 base64 数据返回。官方文档也说明，编辑接口可接收多张参考图，适合本产品的“参考图 + 编辑需求”工作流。

官方参考：

- OpenAI Image generation guide：https://platform.openai.com/docs/guides/images/image-generation
- OpenAI Images API reference：https://platform.openai.com/docs/api-reference/images

### 7.1 模型策略

设计图默认展示：

```text
gpt-image-2
```

落地时建议这样处理：

- 前端默认显示“推荐模型”，不把模型名写死在页面逻辑里。
- 后台配置实际模型 ID。
- 启动时通过配置或健康检查确认模型是否可用。
- 如果 `gpt-image-2` 在目标账号不可用，则降级到当前可用的 GPT Image 模型。

模型配置示例：

```json
{
  "defaultImageModel": "gpt-image-2",
  "fallbackImageModels": ["gpt-image-1.5", "gpt-image-1", "gpt-image-1-mini"],
  "defaultQuality": "high",
  "defaultSize": "1024x1536"
}
```

### 7.2 生成接口封装

后端内部接口：

```http
POST /api/image-tasks
```

请求示例：

```json
{
  "projectId": "project_001",
  "mode": "generate",
  "prompt": "一张干净的产品照片：薰衣草紫水晶珠与珍珠点缀的手链，放在透明亚克力托盘上。",
  "presetId": "product_photography",
  "model": "gpt-image-2",
  "size": "1024x1536",
  "quality": "high",
  "outputFormat": "png",
  "count": 1
}
```

返回示例：

```json
{
  "taskId": "task_001",
  "status": "queued"
}
```

### 7.3 编辑接口封装

后端内部接口：

```http
POST /api/image-edit-tasks
```

表单字段：

- `projectId`
- `prompt`
- `presetId`
- `model`
- `size`
- `quality`
- `images[]`

适用场景：

- 替换商品背景。
- 统一指甲/衣袖/道具风格。
- 生成小红书/ins 风场景图。
- 基于 UI 截图做中文化视觉预览。
- 用产品图生成多张广告场景图。

### 7.4 批量任务封装

后端接口：

```http
POST /api/batch-image-tasks
```

请求示例：

```json
{
  "projectId": "project_001",
  "presetId": "product_photography",
  "items": [
    {
      "name": "bracelet_shot_01.png",
      "prompt": "紫水晶手链，透明亚克力托盘，柔和日光，ins 风"
    },
    {
      "name": "bracelet_shot_02.png",
      "prompt": "紫水晶手链，白色大理石桌面，浅粉花朵背景，特写"
    }
  ],
  "model": "gpt-image-2",
  "size": "1024x1536",
  "quality": "high",
  "outputFormat": "png"
}
```

### 7.5 提示词增强

用户输入：

```text
紫水晶手链，ins风，背景干净
```

系统增强后：

```text
生成一张高保真电商产品摄影图。主体是一条薰衣草紫水晶珠手链，带珍珠和银色钻饰点缀，放在透明亚克力托盘上。背景为干净的 ins 风浅色桌面，柔和自然光，白色与浅粉色美学，画面优雅极简。保持手链清晰、材质通透、反光自然。不要文字、不要水印、不要 logo、不要多余手指、不要畸变。
```

建议把提示词拆成结构化字段：

- 主体。
- 场景。
- 风格。
- 构图。
- 光线。
- 材质。
- 必须保留。
- 必须避免。

## 9. API 设计

项目：

- `GET /api/projects`
- `POST /api/projects`
- `GET /api/projects/:id`
- `PATCH /api/projects/:id`

素材：

- `POST /api/assets/upload`
- `GET /api/assets?projectId=xxx`
- `DELETE /api/assets/:id`

图片任务：

- `POST /api/image-tasks`
- `POST /api/image-edit-tasks`
- `POST /api/batch-image-tasks`
- `GET /api/image-tasks/:id`
- `GET /api/projects/:id/image-tasks`
- `POST /api/image-tasks/:id/retry`
- `POST /api/image-tasks/:id/cancel`

预设：

- `GET /api/presets`
- `POST /api/presets`
- `PATCH /api/presets/:id`

配置：

- `GET /api/settings/image-models`
- `PATCH /api/settings/image-models`
- `GET /api/settings/usage`

实时进度：

- `GET /api/tasks/events`，SSE 方案。
- 或 `WS /ws/tasks`，WebSocket 方案。

MVP 阶段建议先用轮询，每 2 秒查询一次任务状态；生产阶段再升级为 SSE 或 WebSocket。

## 10. 安全与合规

API Key 安全：

- OpenAI API Key 只保存在服务端环境变量或密钥管理系统。
- 浏览器端只能调用自己的后端接口。
- 管理后台仅展示“已连接/未连接”，不明文展示完整 Key。

上传安全：

- 限制文件类型和大小。
- 对上传图片做 hash，避免重复存储。
- 对文件名做清洗，避免路径注入。
- 对图片做基础解析，拒绝损坏文件。

内容合规：

- 禁止直接提供“去除第三方水印”的功能按钮。
- 对用户需求做合规提示：可以基于参考图重新生成原创图，不直接擦除权利标识。
- 保存生成任务日志，方便审计。
- 必要时接入内容审核。

成本安全：

- 用户级每日额度。
- 项目级预算。
- 批量任务并发上限。
- 高质量/大尺寸任务二次确认。
- 失败重试限制。

## 11. 部署方案

### 11.1 MVP 单机部署

适合内部试用：

```text
一台云服务器
  - Nginx
  - Node.js API
  - Worker 进程
  - PostgreSQL
  - Redis
  - 本地或对象存储图片
```

优点：

- 成本低。
- 上线快。
- 方便验证业务流程。

缺点：

- 扩容能力有限。
- 本地图片存储不适合长期生产。

### 11.2 生产部署

建议：

```text
前端：静态站点 / CDN
后端：Docker + 云服务器 / 容器服务
数据库：云 PostgreSQL
队列：云 Redis
对象存储：OSS / COS / R2 / S3
CDN：图片加速
日志：Sentry + 云日志
监控：接口延迟、失败率、队列堆积、成本
```

## 12. MVP 开发计划

### 第 1 阶段：可用原型，3-5 天

目标：跑通“提示词生成图片”闭环。

交付：

- 中文版图像工坊工作台。
- 提示词输入。
- 参数选择。
- 后端 OpenAI 图片生成封装。
- 单张结果展示与下载。
- `.env` 配置 API Key。

验收：

- 用户可以输入提示词生成一张图片。
- 图片能在右侧结果区展示。
- 图片能下载到本地。
- API Key 不出现在浏览器代码中。

### 第 2 阶段：参考图编辑，3-5 天

目标：支持上传图片作为参考，生成新版本。

交付：

- 参考图上传。
- 多图参考。
- 编辑模式。
- 原图和结果图关联。
- 失败提示。

验收：

- 用户上传商品图后可以生成新背景/新风格图片。
- 结果图与原图保留关联记录。

### 第 3 阶段：批量队列，5-8 天

目标：支持电商批量出图。

交付：

- 多行提示词批量任务。
- 队列状态。
- 进度刷新。
- 失败重试。
- 批量下载。

验收：

- 至少 20 条提示词可以稳定排队生成。
- 失败任务不影响已完成任务。
- 可查看每个任务的状态和结果。

### 第 4 阶段：素材库与预设，5-7 天

目标：形成可复用资产体系。

交付：

- 项目管理。
- 素材库。
- 提示词预设。
- 历史记录。
- 收藏与复用。

验收：

- 用户可以按项目找回历史图片。
- 用户可以一键复用历史提示词。
- 管理员可以维护预设模板。

## 13. 成本控制策略

优先级：

1. 默认使用中等或自动质量，用户确认后再用高质量。
2. 批量任务默认低并发，例如 2-3 个 Worker。
3. 对重复提示词和重复参考图做 hash，避免重复生成。
4. 缩略图单独生成，列表页不加载原图。
5. 图片下载走对象存储和 CDN，不走后端转发。
6. 记录每个任务的模型、尺寸、质量、用量，后续做成本报表。

额度展示：

- 顶部显示“已用额度 / 总额度”。
- 批量任务开始前预估消耗。
- 超过预算时暂停队列。

## 14. 风险与应对

AI 结果不稳定：

- 通过预设模板降低提示词随机性。
- 保留优秀结果对应的提示词。
- 引入人工评分，沉淀高质量模板。

编辑不够精确：

- 对“必须保留”和“必须改变”做结构化提示词。
- 后续支持遮罩编辑。
- 重要商品图保留人工复核环节。

成本不可控：

- 设置日额度、项目额度、批量并发。
- 高质量和大尺寸任务提示确认。
- 建立任务用量流水。

接口限流：

- 队列化处理。
- 指数退避重试。
- 按用户和项目限流。

素材版权：

- 只允许上传自有素材或已授权素材。
- 对水印去除类需求做拦截，引导为原创重生成。
- 保存用户操作日志。

## 15. 关键验收标准

产品验收：

- 界面与设计图一致：左侧导航、中间生成区、右侧结果区、底部队列。
- 中文文案完整，无英文残留，模型名和文件名除外。
- 生成、编辑、批量三个模式可切换。
- 结果图可下载、可回看。

技术验收：

- API Key 不暴露在前端。
- 图片生成任务不阻塞主接口。
- 批量任务有状态和失败重试。
- 数据库保存任务参数、结果 URL、用量。
- 上传图片进入对象存储。
- 具备日志和错误追踪。

运营验收：

- 一个运营人员可以在 10 分钟内完成 5 张商品图生成。
- 批量队列可以稳定处理 20 张以上图片。
- 常用风格预设可复用。
- 成本可以按项目查看。

## 16. 推荐下一步

第一步先做 MVP，不追求一次性做完整 SaaS：

- 完成中文工作台前端。
- 接入服务端 OpenAI 图片生成。
- 支持参考图上传和单张编辑。
- 支持本地项目级历史记录。

第二步再做批量队列和素材库：

- Redis 队列。
- Worker 生成。
- 对象存储。
- 批量下载。

第三步做商业化能力：

- 用户权限。
- 额度与成本。
- 店铺/商品维度素材管理。
- 电商平台导出格式。

## 17. 方案结论

“图像工坊”的技术落地难点不在页面本身，而在稳定的生产链路：提示词标准化、参考图管理、任务队列、成本控制、结果沉淀和合规边界。建议采用“前端工作台 + 后端 AI 网关 + 队列 Worker + 对象存储 + 数据库”的架构，先用 MVP 验证电商出图流程，再逐步扩展为可复用的图片生产系统。

这套方案可以优先服务刘刘电商当前的商品图和社媒图生产，再沉淀为内部 AI 图片工具，后续也可以包装成面向中小电商团队的 SaaS 产品。
