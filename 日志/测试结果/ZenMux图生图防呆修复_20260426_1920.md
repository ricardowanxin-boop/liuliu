# ZenMux 图生图防呆修复 2026-04-26 19:20

## 背景

ZenMux `openai/gpt-image-2` 经过直连诊断后确认：

- 文字生图 `generate_images` 可用。
- 参考图编辑 `edit_image` 返回 `500 Resource not found`。

因此不能继续把它作为当前产品的图生图默认可用通道，否则会让测试人员误以为是提示词、质量算法或商品保护策略失败。

## 本次修复

1. 后端新增模型能力描述：
   - `/api/config` 会返回 `modelCapabilities`。
   - `zenmux/openai/gpt-image-2` 标记为 `imageEditEnabled=false`。

2. 后端新增请求防呆：
   - 如果用户仍然提交 `zenmux + openai/gpt-image-2` 的图生图请求，直接返回 HTTP 400。
   - 不再进入真实模型调用，避免继续扣费。

3. 前端新增选择提示：
   - 模型参数区显示“当前模型不可用于图生图”。
   - 生成按钮会被禁用。

## 验证

- Python 编译通过：`python3 -m compileall backend scripts`
- React 构建通过：`npm --prefix frontend run build`
- `/api/config` 已返回：
  - `imageEditEnabled: false`
  - `imageEditNote: ZenMux openai/gpt-image-2 已验证文字生图可用，但图片编辑接口当前返回 Resource not found。请切换到支持图生图的模型或通道。`
- 本地阻断测试返回 HTTP 400，不触发真实模型调用。

## 下一步

继续推进时应优先确认一个“真实可图生图”的主通道：

1. ZenMux 其他 Gemini 图像模型：需要单次真实接口验证。
2. Doubao 原生通道：已能图生图，但质量问题仍需依赖分层编辑和质检。
3. OpenAI-compatible 通道：如果能补齐可用 Key，可作为 GPT-image 主链路。
